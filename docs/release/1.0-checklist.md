# Steno 1.0 Acceptance and Release Checklist

## Current stage

Version 1.0 is an unreleased candidate. The original unwanted repeated-Terms bug is closed after maintainer testing. The selected interface is Manuscript, including the compact Dictate pill, bounded live-transcript overlay, persistent Settings drafts, responsive History and Insights, clearer onboarding, and ribbon S identity.

Candidate metadata is `1.0.0`, build `3` in `project.yml`. This does not establish a public release. Local automated tests, synthetic visual checks, and an ad-hoc signed Debug app are development evidence. Final release-source acceptance and a Developer ID signed, notarized distribution artifact remain pending.

This checklist is preparation. It does not authorize merging, tagging, signing/notarization submission, uploading, publishing, or changing the website. Retain the existing public download until a replacement is approved and verified.

### September 8 bug closeout

**Closed: unwanted repeated "Terms" output without corresponding speech.** The retained helper verifies suspected prompt-derived text using acoustic support and prompt-free corroboration. The maintainer reports no recent recurrence and has accepted the installed fix. Fresh quiet-onset, ordinary-dictation, and deliberate repeated-Terms tests have matching stored raw and cleaned transcripts. The original bug requires no further investigation unless a new recurrence is reported. Broader release acceptance remains separate.

Two accuracy limitations are deferred from this closed bug. One retained recording loses words during final VAD preparation after a long quiet lead-in, although a fresh rendition succeeds on the installed version. A separate small.en test transcribes deliberately spoken "Terms" as "Churns" on both the existing helper and an experimental helper. Neither result establishes a recurrence of unwanted Terms fabrication. The experimental VAD change was not accepted or installed and is excluded from the candidate. These limitations remain documented for the eventual release decision.

## Automated source checks

Use the shared [CI/CD pipeline](../ci-cd.md) for the selected release source. Confirm both aggregate gates passed on GitHub and [repository enforcement](../maintainers/github-setup.md) is active. Hosted CPU checks and the single public-audio smoke fixture do not replace native Metal acceptance or the broader evaluation below.

- [ ] Package tests pass on the chosen source: `swift test --package-path StenoKit`.
- [ ] The generated project matches `project.yml`: `xcodegen generate`.
- [ ] Hosted macOS tests pass: `xcodebuild test -project Steno.xcodeproj -scheme Steno -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO`.
- [ ] The normal app builds: `xcodebuild build -project Steno.xcodeproj -scheme Steno -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO`.
- [ ] Required benchmark/report and zero-regression checks pass for transcription/runtime, cleanup, ranking, or benchmark changes; final release evaluation follows [release-eval.md](release-eval.md).
- [ ] Evaluation names its corpus, baseline, model/hardware/runtime identities, and limitations. `not_evaluable` remains distinct from a pass.
- [ ] Source and staged artifacts contain no personal signing settings, private paths, review data, or generated research bundles.

The confirmed-silence optimization reduces optional preview work under positive VAD evidence. It does not establish better final ASR accuracy. Synthetic overlay layout and app-state tests do not establish live microphone or supported-player behavior.

## Distribution and publication gates

Follow [direct-distribution.md](direct-distribution.md) only when packaging is authorized.

- [ ] Select and approve the intended release source, including disposition of documented accuracy limitations and any newly requested changes.
- [ ] Inspect live remote/base state and reconcile the approved integration path; do not assume local `main` is current.
- [ ] Verify the required Developer ID certificate and notarization setup without exposing credentials.
- [ ] Build the self-contained Release app and DMG with the pinned local runtime, helper, dylibs, models, resources, and notices.
- [ ] Verify that the installed distribution uses the matched prompt-verification helper. An older helper or CLI fallback does not establish the same recognition behavior.
- [ ] Verify Developer ID signatures, notarization, stapling, and Gatekeeper results on the exact distribution artifact.
- [ ] Install from the DMG and verify first launch, permissions, bundled dependencies, and dictation on the intended support matrix.
- [ ] Replace historical screenshots and finalize README, Quickstart, changelog/release notes, and version/build metadata for the approved release.
- [ ] Obtain approval for final public text and release actions; integrate, tag, push, and publish only as authorized.
- [ ] Verify remote commit/tag, release object, downloadable asset, and published checksums.
- [ ] Update download links only after the released asset is verified. Website changes remain a separately scoped deliverable.

Keep this checklist pending until the corresponding receipts exist. A passing local build or completed documentation update does not close the release gates.
